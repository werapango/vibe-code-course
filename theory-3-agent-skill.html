🪙 context ยาวขึ้น ก็ใช้ token มากขึ้น

ทุกไฟล์ที่ agent อ่าน ทุกข้อความในแชต และทุกผลลัพธ์ของคำสั่ง ถูกนับเป็น token (หน่วยนับข้อความที่ใช้คิดโควต้าของ AI) ซ้ำทุกรอบของ loop ยิ่งแชตยาว log ยาว หรือให้อ่านไฟล์ที่ไม่เกี่ยว ก็ยิ่งเปลืองโควต้าขึ้นเรื่อย ๆ จึงมีกติกา 3 ข้อ: สั่ง 1 task ต่อ 1 prompt, จบแต่ละ lab ให้เปิด session ใหม่, และเวลาแจ้ง error ให้แปะเฉพาะบรรทัดที่เกี่ยว

ข้อห้ามของ agent: ทำไม agent ห้ามรันคำสั่งเอง

ข้อห้ามแบบนี้เรียกว่า guardrail (ข้อจำกัดที่กันไม่ให้ agent ทำเกินขอบเขต) AGENTS.md ของ starter เขียนไว้ว่า ห้ามรัน wrangler, npm install, git เอง ให้เขียนคำสั่งไว้ท้ายคำตอบให้คนรันแทน ด้วยเหตุผล 3 ข้อ:

  1. ความปลอดภัย — คำสั่งอย่าง migrations apply --remote, deploy, d1 execute แก้ฐานข้อมูลหรือระบบที่ใช้งานจริง การตัดสินใจนี้ต้องเป็นของคน
  2. ประหยัด token — ผลของคำสั่ง (เช่น log การติดตั้ง ตาราง migration) ยาวมาก ถ้า agent รันเอง ข้อความเหล่านี้จะเข้าไปอยู่ใน context และถูกนับซ้ำทุกรอบ
  3. ความเข้าใจ — คนที่รันคำสั่งเองรู้ว่าระบบอยู่ในสถานะไหน (local/remote, migrate แล้วหรือยัง)
💡 ข้อห้ามนี้ใช้กับการเรียนวันนี้ ไม่ได้แปลว่าห้ามตลอดไป

ในงานจริงมีเครื่องมือที่ให้ agent จัดการ Cloudflare เองได้ เช่น Cloudflare agent setup ที่ติดตั้งความรู้เรื่อง Cloudflare (skills) และเชื่อม agent กับบัญชีของเรา (MCP) วันนี้จะลองใช้ตอนท้าย Lab 4 ข้อ 4 หลังจากพิมพ์คำสั่งเองมาทั้งวันแล้ว เพราะถ้าไม่เคยพิมพ์เอง ก็จะตัดสินไม่ได้ว่าคำสั่งที่ agent ขอรันนั้นปลอดภัยหรือไม่ และตอนนั้นต้องเขียนข้อยกเว้นของกติกาใน AGENTS.md ให้ชัด ซึ่งก็คือการปรับกติกาของ agent (ขั้น Improve ใน ADLC ด้านล่าง)

ADLC: วงจรการพัฒนา agent/skill

ADLC ย่อมาจาก Agent Development Life Cycle (วงจรการพัฒนา agent) เป็นคำที่ยังไม่มีนิยามมาตรฐานเดียว แต่แนวคิดหลักคือ AGENTS.md และ skill ก็เหมือนซอฟต์แวร์ ต้องเขียน ลองใช้ แล้วปรับปรุงเป็นรอบ ๆ แบบเดียวกับ SDLC (วงจรการพัฒนาซอฟต์แวร์)
