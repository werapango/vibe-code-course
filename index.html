📖 แนวคิดหลัก

ยุคที่ AI เขียนโค้ดแทน คอขวดย้ายไปอยู่ที่ “บอกให้ชัดว่าต้องการอะไร” และ “พิสูจน์ว่าที่ได้มาถูกจริง” — วันนี้จึงฝึกทั้ง validation (สร้างของที่ใช่: spec ตรงความต้องการจริงไหม) และ verification (สร้างถูกวิธี: โค้ดตรง spec ไหม)

จุดประสงค์การเรียนรู้

  1. อธิบาย SDLC และบอกได้ว่าแต่ละ phase ผลิตอะไร AI เข้ามาช่วยหรือเปลี่ยนอะไร
  2. หาความต้องการจริง: ระบุ stakeholder ถามเจ้าของโจทย์ เขียน use case, user story, FR/NFR ที่มีที่มาและวัดได้
  3. เขียน Spec ที่ตรวจสอบได้: acceptance criteria แบบ Given/When/Then ตารางตัวอย่าง และตามรอย requirement → test ด้วย npm run trace
  4. ออกแบบเบื้องต้น: สถาปัตยกรรม ที่ deploy tech stack ข้อมูล API และบันทึกเหตุผลเป็น ADR
  5. แตกงานเป็น WBS และใช้ Agent & Skill ให้ทำงานทีละ task อย่างมีวินัย (เข้าใจ ADLC)
  6. ใช้คำสั่ง Cloudflare เอง ตั้งแต่สร้างโปรเจกต์ ฐานข้อมูล migration deploy rollback จนตรวจ log

ละเอียดรายช่วง: ตารางเวลา

หลักการ 5 ข้อ

1 · คำสั่ง Cloudflare คนพิมพ์เอง

สร้างโปรเจกต์ ฐานข้อมูล migration deploy rollback — agent ห้ามรันคำสั่งแทน (เขียนไว้ใน AGENTS.md)

2 · ทุก requirement มีที่มา

มาจากโจทย์หรือคำตอบของเจ้าของโจทย์ ข้อที่ AI เดาเองติดป้าย [สมมติฐาน] จนกว่าจะยืนยัน

3 · ทุก AC ตรวจได้

Given/When/Then มีผลลัพธ์เป็นรูปธรรม ทุก AC มี smoke test — npm run trace เป็นคนตัดสิน

4 · 1 task = 1 prompt

สั่ง agent ทีละ task จาก TASKS.md เช่น ทำ task T1.1 ใน TASKS.md แล้วคนตรวจ diff ก่อน commit

5 · Deploy เร็ว ถอยได้

ได้ URL จริงตั้งแต่ชั่วโมงแรก และรู้วิธี rollback ก่อนจะต้องใช้จริง
