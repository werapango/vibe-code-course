Lab 1a — Vibe warm-up (20 นาที)

ลองแบบ “vibe coding” ของแท้: พูดสิ่งที่อยากได้ → AI สร้าง → ขึ้นอินเทอร์เน็ต — ไม่มี spec ไม่มีการทดสอบ เพื่อให้รู้สึกทั้งความเร็วและขีดจำกัดของวิธีนี้

🎯 เจตนา

mkdir -p hello-vibe/site && cd hello-vibe

สั่งงานแรก + สังเกต agent loop · 6 นาที

🎯 เจตนา

ให้ agent สร้างหน้าเว็บไฟล์เดียว แล้วดูว่ามันทำงานเป็นวงอย่างไร (วางแผน → แก้ไฟล์ → สรุป) — ทฤษฎี 3 ช่วงบ่ายจะอ้างกลับมาที่สิ่งที่คุณเห็นตรงนี้

💬 พิมพ์ให้ ZCode (แก้ข้อความใน [ ])
สร้างไฟล์ site/index.html ไฟล์เดียว (CSS ฝังในไฟล์ ไม่ต้องมีไฟล์อื่น)
เป็นหน้าแนะนำ [ตัวฉัน / หน่วยงานของฉัน] มีหัวเรื่องใหญ่ คำโปรย 1 ประโยค และการ์ด 3 ใบ
โทนสี [อบอุ่น / เย็น / มินิมอล] อ่านภาษาไทยสวย และใช้บนมือถือได้
ห้ามรันคำสั่งใด ๆ

ระหว่างรอ ติ๊กเช็กลิสต์:

  • agent แสดงแผนก่อนลงมือไหม
  • agent สร้าง/แก้ไฟล์อะไรบ้าง (ควรเป็น site/index.html ไฟล์เดียว)
  • agent พยายามรันคำสั่งอะไรไหม
  • เสร็จแล้ว agent สรุปผลอย่างไร

Deploy ด้วยคำสั่งเดียว · 5 นาที

🎯 เจตนา

อัปโหลดโฟลเดอร์ site ขึ้น Cloudflare เป็นเว็บแบบไฟล์อย่างเดียว (static assets) โดยไม่ต้องมีโปรเจกต์หรือไฟล์ตั้งค่า — --name คือชื่อ Worker (ส่วนหน้าของ URL) เปลี่ยน somchai เป็นชื่อของคุณ

npx wrangler deploy --assets ./site --name hello-somchai --compatibility-date 2025-11-01

ถ้าเป็นการ deploy ครั้งแรกของบัญชี wrangler จะให้ตั้งชื่อ subdomain workers.dev — ตั้งตามที่ถาม (ทำครั้งเดียว ใช้กับทุกแอปของคุณ) แล้วเปิด URL https://hello-somchai.<subdomain>.workers.dev จากเบราว์เซอร์และมือถือ

จะเก็บเว็บนี้ไว้หรือลบก็ได้ ลบด้วย npx wrangler delete hello-somchai (ตอบ y)

Lab 1b — Starter สู่ production (35 นาที · 0 token)

ทุกคำสั่งต่อจากนี้ คนพิมพ์เอง — ไม่ใช้ ZCode เลย เพื่อให้เห็นว่า deploy ระบบที่มีฐานข้อมูลและระบบผู้ใช้ไม่ต้องใช้ AI สักบรรทัด

1

ดึง starter ด้วยคำสั่ง Cloudflare · 4 นาที

🎯 เจตนา

ใช้ C3 (create-cloudflare) ดึงโครงเริ่มต้นจาก GitHub มาเป็นโฟลเดอร์ my-app และติดตั้ง dependency ให้ — ทุกคนในห้องได้โครงเดียวกัน · --no-deploy ยังไม่ deploy · --no-git เราตั้ง Git เองในขั้น 6 · --no-agents ไม่ให้ C3 เขียน AGENTS.md ของ Cloudflare ทับของโปรเจกต์

กลับไปโฟลเดอร์ทำงาน (ออกจาก hello-vibe) ก่อน:

cd ..
npm create cloudflare@latest my-app -- --template=werapango/workers-app-starter --no-deploy --no-git --no-agents
cd my-app

C3 ตั้งชื่อ Worker (name ใน wrangler.jsonc) ตามชื่อโฟลเดอร์ และจัดรูปแบบไฟล์ใหม่เล็กน้อย — ปกติ · คำเตือน npm warn install-scripts … esbuild / workerd ไม่ต้องทำอะไร

2

🎯 เจตนา

เห็นว่าแต่ละโฟลเดอร์อยู่ส่วนไหนของสถาปัตยกรรม และเห็นด้วยตาว่าแอปที่ “ยังไม่มีฐานข้อมูล” เป็นอย่างไร

3

สร้างฐานข้อมูล D1 · 3 นาที

🎯 เจตนา

สร้างฐานข้อมูลบนคลาวด์ชื่อ app-db และให้ wrangler เขียนการเชื่อมต่อ (binding ชื่อ DB) ลงใน wrangler.jsonc ให้เอง

npx wrangler d1 create app-db --binding DB --update-config

เปิด wrangler.jsonc ต้องเห็นส่วน "d1_databases" ที่มี database_id ของคุณ (ถ้าไม่มี ดูปัญหาที่พบบ่อย)

4

Migration ในเครื่อง + ตั้งค่าครั้งแรก · 6 นาที

🎯 เจตนา

สร้างตาราง users, sessions ในฐานข้อมูลจำลองบนเครื่อง (--local) แล้วลองระบบผู้ใช้ที่ starter มีให้

npx wrangler d1 migrations apply app-db --local

ถามยืนยัน ตอบ y

npm run dev
  1. /api/health ต้องเป็น "db": "ready"
  2. เปิด http://localhost:8787 → หน้า ตั้งค่าครั้งแรก → สร้าง admin (ชื่อ/รหัสของคุณ จำไว้)
  3. เมนู ผู้ใช้ → เพิ่มผู้ใช้ทั่วไป 1 คน
  4. กด F12 → แท็บ Network ล็อกเอาต์แล้วล็อกอินใหม่ ดูคำขอ /api/auth/login (method, status, JSON) → แท็บ Application → Cookies เห็น session ที่ติ๊ก HttpOnly
5

ทดสอบตาม acceptance criteria · 3 นาที

🎯 เจตนา

ให้สคริปต์เรียก API จริงตาม AC ทุกข้อใน SPEC.md แทนการคลิกเอง — บอก smoke test ด้วยว่า admin ของคุณชื่ออะไร (เปิด terminal ที่สอง ปล่อย dev รันไว้)

SMOKE_ADMIN_USER=ชื่อadmin SMOKE_ADMIN_PASS=รหัสadmin npm run smoke
npm run trace

smoke ต้องผ่านทั้งหมด (AC-A1.1 จะ “ข้าม” เพราะฐานข้อมูลมีผู้ใช้แล้ว) · trace ต้องขึ้น ✅ ตามรอยครบ

PowerShell: $env:SMOKE_ADMIN_USER="..."; $env:SMOKE_ADMIN_PASS="..."; npm run smoke

6

ปัก checkpoint แรกด้วย Git · 3 นาที

🎯 เจตนา

จุดย้อนกลับที่ปลอดภัยก่อนทำอะไรต่อ · ตั้งชื่อ/อีเมลเฉพาะโปรเจกต์นี้ (ไม่ใช้ --global) เพราะเครื่อง Lab เป็นของส่วนกลาง

7

ขึ้น production + สร้าง admin ทันที · 6 นาที

🎯 เจตนา

ฐานข้อมูลบนคลาวด์เป็นคนละตัวกับในเครื่อง จึงต้องรัน migration กับ --remote ก่อน แล้วค่อยอัปโหลดโค้ด

npx wrangler d1 migrations apply app-db --remote
npx wrangler deploy

อ่านผลทีละบรรทัด: ขนาดที่อัปโหลด (Total Upload) · ไฟล์ assets ที่ขึ้นไป · binding DB · URL · Current Version ID

⚠ เปิด URL แล้วสร้าง admin ทันที

หน้าตั้งค่าครั้งแรกเปิดให้ใครก็ได้ที่รู้ URL จนกว่าจะมีผู้ใช้คนแรก — ใครถึงก่อนได้เป็น admin นี่คือความเสี่ยงด้านความปลอดภัยจริงที่ต้องปิดให้เร็วที่สุด

สร้าง admin บน production แล้วเปิด URL จากมือถือ ล็อกอินให้ได้

8

Release เวอร์ชัน 2 แล้ว rollback · 4 นาที

🎯 เจตนา

พิสูจน์ด้วยมือว่าทุก release ถอยกลับได้ — เมื่อถอยได้ เราจึงกล้า deploy บ่อย

แก้ข้อความใน public/index.html เช่นเปลี่ยน 🚀 แอปของฉัน เป็น 🚀 แอปของฉัน v2 แล้ว:

npx wrangler deploy
npx wrangler deployments list
npx wrangler rollback

รีเฟรชหน้าเว็บ → กลับเป็นข้อความเดิม · ตรวจให้แน่ใจด้วย deployments list อีกครั้ง แล้ว deploy คืนเป็น v2 และ commit

npx wrangler deploy
git commit -am "lab 1: v2 title"

ดู log ของ production แบบสด · 1 นาที

🎯 เจตนา

observability: รู้ว่าเกิดอะไรขึ้นบน production โดยไม่ต้องเดา

npx wrangler tail

รีเฟรชหน้าเว็บจากมือถือ → เห็นคำขอวิ่งเข้ามา → Ctrl+C · (เปิด dashboard → Workers & Pages → Worker ของคุณ ดู metrics และ versions ได้ด้วย)

✅ ผ่าน Lab 1b เมื่อ
  • https://my-app.<subdomain>.workers.dev เปิดจากมือถือได้ และล็อกอิน admin บน production ได้
  • smoke ในเครื่องผ่าน + trace ครบ
  • ลอง rollback สำเร็จ และมี commit อย่างน้อย 2 ครั้ง
🆘 ถ้าตามไม่ทัน

ขอโฟลเดอร์ lab1-done จากไดรฟ์ร่วมของห้อง → คัดลอกมาเป็น my-app → npm install → แก้ database_id ใน wrangler.jsonc เป็นของคุณ (จากผล d1 create หรือ npx wrangler d1 list) → migrations apply --local และ --remote → deploy → สร้าง admin ทันที

ส่วนที่ 1 — บริบท (ส่งครั้งแรกครั้งเดียว)

ฉันจะสร้าง "starter" สำหรับเว็บแอปบน Cloudflare ที่นำไปต่อยอดได้ทุกโจทย์ ทำทีละ task ตามที่ฉันสั่งเท่านั้น

เป้าหมาย: โครงเว็บแอปที่ deploy ได้ทันที มีระบบเข้าสู่ระบบและจัดการผู้ใช้แบบง่าย
มีเอกสารและการทดสอบพร้อมให้ต่อยอดแบบ spec-driven

ข้อจำกัด:
- Cloudflare Workers + Hono (TypeScript) + D1 (binding ชื่อ DB, ฐานข้อมูลชื่อ app-db) + Static Assets (โฟลเดอร์ public/)
- ต้องอยู่ใน free plan ห้ามใช้บริการที่ต้องผูกบัตร (Access, R2, Email)
- หน้าเว็บเป็น HTML/CSS/JS ธรรมดา ไม่ใช้ framework รองรับมือถือ
- ห้ามเพิ่ม dependency นอกจาก hono โดยไม่ถาม
- SQL ทุกคำสั่งต้องเป็น prepared statement · เปลี่ยน schema ด้วยไฟล์ migration ใหม่เท่านั้น
- คอมเมนต์และข้อความ error เป็นภาษาไทย · API ตอบ JSON รูปแบบ { "error": "..." } พร้อม status ที่ถูกต้อง
- route 1 เรื่อง = 1 ไฟล์ใน src/routes/

กติกาการทำงาน:
- ห้ามรัน wrangler, npm, git เอง ให้เขียนคำสั่งที่ฉันต้องรันไว้ท้ายคำตอบ
- ถ้าข้อมูลไม่พอ ให้ถามก่อน ห้ามเดา
- จบแต่ละ task ตอบ 3 ส่วน: ไฟล์ที่แก้ / คำสั่งที่ต้องรัน / วิธีทดสอบ

ส่วนที่ 3 — task (ส่งทีละข้อ แล้ว commit หลังแต่ละข้อ)

T1 โครงแอป

ทำ T1: แปลง src/index.ts เป็น Hono แยก route ไว้ใน src/routes/ เพิ่ม GET /api/health ตอบ { ok: true, db, time }
โดย db บอกสถานะฐานข้อมูล ("ready" / "no-binding" / "not-migrated"), ดัก 404 และ 500 เป็น JSON,
ตั้ง wrangler.jsonc ให้มี assets (public/) และ observability พร้อมคอมเมนต์ภาษาไทยทุกส่วน
เสร็จเมื่อ: npm run dev แล้ว /api/health ตอบ 200 และหน้า public/index.html เรียก API นี้แสดงผลได้

T2 การทดสอบ

ทำ T2: สร้าง scripts/smoke.mjs (เรียก API จริง, จำ cookie ได้แบบเบราว์เซอร์, เปลี่ยน local/production ด้วย BASE_URL,
ชื่อเคสขึ้นต้นด้วยรหัส AC, รายงาน ผ่าน/ไม่ผ่าน/ข้าม) และ scripts/trace.mjs (ตรวจว่า AC ตัวหนาทุกข้อใน SPEC.md
มีเคสใน smoke.mjs และทุกเคสอ้าง AC ที่มีจริง, เตือนถ้า FR ใน docs/SRS.md ไม่ถูกอ้างใน SPEC.md)
เพิ่ม npm scripts: dev, deploy, smoke, trace

👤 หลัง T2 สร้างฐานข้อมูล:

npx wrangler d1 create app-db --binding DB --update-config

T3 ฐานข้อมูลผู้ใช้ + ไลบรารี auth

ทำ T3: migration ตาราง users (username unique, password_hash, role admin/user, created_at)
และ sessions (token, user_id อ้าง users ลบตาม, expires_at) + src/lib/auth.ts:
hash ด้วย PBKDF2-SHA256 100,000 รอบ + salt สุ่ม เก็บเป็น "salt:hash", session token สุ่ม 32 ไบต์ อายุ 7 วัน,
cookie HttpOnly + SameSite=Lax (Secure เมื่อเป็น https), middleware requireAuth (ฝาก userId, username, role ใน context)
และ requireAdmin (403 ถ้าไม่ใช่ admin)

👤 หลัง T3:

npx wrangler d1 migrations apply app-db --local

T4 API ผู้ใช้

ทำ T4: /api/auth/setup (GET บอกว่ายังไม่มีผู้ใช้ไหม, POST สร้าง admin คนแรกได้เฉพาะตอนยังไม่มีผู้ใช้ แล้วล็อกอินให้),
login, logout, me, PUT password (เปลี่ยนรหัสของตัวเอง ต้องยืนยันรหัสเดิม)
และ /api/users CRUD สำหรับ admin เท่านั้น (ไม่ส่ง password_hash ออกไป)
กติกา: ล็อกอินผิดตอบข้อความเดียวกันไม่ว่าชื่อหรือรหัสผิด, admin ลบตัวเองไม่ได้, ต้องเหลือ admin อย่างน้อย 1 คน,
admin ตั้งรหัสใหม่ให้ใครแล้ว session เดิมของคนนั้นต้องใช้ไม่ได้
เพิ่มเคส smoke ครบทุกกติกา

T5 หน้าเว็บ

ทำ T5: หน้าเดียวหลาย view สลับด้วย #hash: ตั้งค่าครั้งแรก, ล็อกอิน, หน้าหลัก (แสดง /api/health),
จัดการผู้ใช้ (admin), เปลี่ยนรหัสผ่าน · แยกไฟล์ index.html / app.css / app.js
ทุกหน้าใช้ fetch เรียก API แสดง error จาก API และ escape ข้อมูลผู้ใช้ก่อนแสดง (กัน XSS)

T6 เอกสาร

ทำ T6: AGENTS.md (stack, โครงไฟล์, กติกาการทำงานแบบในส่วนที่ 1, ตาราง skills),
SPEC.md (ส่วนผู้ใช้และการเข้าสู่ระบบเขียนครบเป็นตัวอย่าง: user story, AC แบบ Given/When/Then ตัวหนาพร้อมรหัส,
data model, API contract, NFR ที่วัดได้) + template เปล่าของ TASKS.md, docs/SRS.md, docs/DESIGN.md,
skills/add-endpoint/SKILL.md, README.md
