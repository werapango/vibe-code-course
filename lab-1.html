Lab 1a — Vibe warm-up (20 นาที)

ลอง “vibe coding” แบบเต็มรูป: บอก AI ว่าอยากได้อะไร ให้ AI สร้าง แล้วเอาขึ้นอินเทอร์เน็ตเลย โดยไม่มี spec (เอกสารที่ระบุว่าระบบต้องทำอะไร) และไม่มีการทดสอบ เพื่อให้เห็นเองว่าวิธีนี้เร็วแค่ไหน และมีข้อจำกัดอะไร

เตรียมโฟลเดอร์ · 2 นาที

🎯 ทำขั้นนี้เพื่ออะไร

agent (AI ที่ลงมือสร้าง/แก้ไฟล์และรันคำสั่งได้เอง) ทำงานได้เฉพาะในโฟลเดอร์ที่เราเปิดให้ จึงสร้างโฟลเดอร์ใหม่ hello-vibe ไว้ให้มันโดยเฉพาะ และมีโฟลเดอร์ย่อย site ไว้เก็บไฟล์ที่จะขึ้นเว็บ · พิมพ์คำสั่งนี้ใน Git Bash

mkdir -p hello-vibe/site && cd hello-vibe

เปิด ZCode ในโฟลเดอร์ hello-vibe แล้วเลือกโมเดล Flash · ตรวจว่าโหมดเป็น Ask before changes (ยังไม่เคยใช้ ZCode? อ่าน ZCode เบื้องต้น ก่อน — หน้าจอ โหมด และควรกดอะไรเมื่อมันขออนุญาต)

2

สั่งงานแรก + สังเกต agent loop · 6 นาที

🎯 ทำขั้นนี้เพื่ออะไร

ให้ agent สร้างหน้าเว็บไฟล์เดียว แล้วสังเกตว่ามันทำงานเป็นรอบอย่างไร: วางแผนก่อน แล้วแก้ไฟล์ แล้วสรุปผล (รอบนี้เรียกว่า agent loop) — ช่วงบรรยายทฤษฎี 3 ตอนบ่ายจะย้อนกลับมาพูดถึงสิ่งที่คุณเห็นตรงนี้

💬 พิมพ์ให้ ZCode (แก้ข้อความใน [ ])
สร้างไฟล์ site/index.html ไฟล์เดียว (CSS ฝังในไฟล์ ไม่ต้องมีไฟล์อื่น)
เป็นหน้าแนะนำ [ตัวฉัน / หน่วยงานของฉัน] มีหัวเรื่องใหญ่ คำโปรย 1 ประโยค และการ์ด 3 ใบ
โทนสี [อบอุ่น / เย็น / มินิมอล] อ่านภาษาไทยสวย และใช้บนมือถือได้
ห้ามรันคำสั่งใด ๆ

ระหว่างรอ ติ๊กเช็กลิสต์:

  • agent แสดงแผนก่อนลงมือไหม
  • agent สร้าง/แก้ไฟล์อะไรบ้าง (ควรเป็น site/index.html ไฟล์เดียว)
  • agent พยายามรันคำสั่งอะไรไหม
  • เสร็จแล้ว agent สรุปผลอย่างไร

start site/index.html

🪙 ประหยัด token

แก้ไม่เกิน 2 รอบแล้วไปต่อ เพราะทุกรอบใช้ token (หน่วยนับปริมาณข้อความที่ AI อ่านและเขียน ใช้มากก็เปลืองโควต้ามาก) — แบบฝึกอุ่นเครื่องนี้ไม่ได้วัดความสวย

Deploy ด้วยคำสั่งเดียว · 5 นาที

🎯 ทำขั้นนี้เพื่ออะไร

อัปโหลดโฟลเดอร์ site ขึ้น Cloudflare เป็นเว็บที่มีแค่ไฟล์ ไม่มีโค้ดฝั่ง server (static assets) โดยไม่ต้องมีโปรเจกต์หรือไฟล์ตั้งค่า · รันใน Git Bash ที่โฟลเดอร์ hello-vibe · --name คือชื่อ Worker (ชื่อแอปบน Cloudflare และเป็นส่วนหน้าของ URL) ให้เปลี่ยน somchai เป็นชื่อของคุณ

npx wrangler deploy --assets ./site --name hello-somchai --compatibility-date 2025-11-01

ถ้าเป็นการ deploy ครั้งแรกของบัญชี wrangler จะให้ตั้งชื่อ subdomain workers.dev — ตั้งตามที่ถาม (ทำครั้งเดียว ใช้กับทุกแอปของคุณ) เมื่อเสร็จ wrangler จะแสดง URL https://hello-somchai.<subdomain>.workers.dev ให้เปิดจากเบราว์เซอร์และมือถือ ถ้าเห็นหน้าเว็บของคุณ แปลว่าสำเร็จ

คุยกัน: วิธีนี้พอไหม? · 3 นาที

📖 คำถามก่อนเริ่ม starter

ถ้าหน้าเว็บนี้ต้อง เก็บข้อมูล · มี ล็อกอิน · ให้ 30 คนใช้พร้อมกัน · และ รู้ว่ามันถูกต้อง — prompt เดียวแบบนี้ยังพอไหม? Vibe coding เหมาะกับการทำต้นแบบเร็ว ๆ แต่ระบบที่ใช้งานจริงต้องมี spec (เอกสารว่าระบบต้องทำอะไร) ต้องแบ่งงานเป็นชิ้นเล็ก และต้องตรวจว่าทำถูก — ซึ่งคือสิ่งที่เราจะฝึกทั้งวัน

จะเก็บเว็บนี้ไว้หรือลบก็ได้ ลบด้วย npx wrangler delete hello-somchai (ตอบ y)

Lab 1b — Starter สู่ production (35 นาที · 0 token)

ทุกคำสั่งต่อจากนี้ คุณพิมพ์เองใน Git Bash ไม่ใช้ ZCode เลย เพื่อให้เห็นว่าการ deploy ระบบที่มีฐานข้อมูลและระบบผู้ใช้ ไม่ต้องใช้ AI เลย

📦 starter นี้มาจากไหน และสร้างเองได้ไหม

วันนี้ดึงโครงที่ผู้สอนเตรียมไว้จาก GitHub (werapango/workers-app-starter) เพื่อไม่ให้เสียโควต้าและเวลา แต่โครงนี้สร้างเองได้ด้วย agent โดยใช้ชุด prompt ที่ผู้สอนใช้สร้างจริง แบ่งเป็น 6 task (โครงแอป → การทดสอบ → ฐานข้อมูลและ auth → API ผู้ใช้ → หน้าเว็บ → เอกสาร) ดูได้ที่ ท้ายหน้านี้ หรือไฟล์ docs/STARTER-PROMPT.md ซึ่งอยู่ในโปรเจกต์ที่คุณกำลังจะดึงมาด้วย — เก็บไว้ใช้วันหลังเมื่อมีโควต้า หรืออยากเปลี่ยนเทคโนโลยีเป็นแบบอื่น

ดึง starter ด้วยคำสั่ง Cloudflare · 4 นาที

🎯 ทำขั้นนี้เพื่ออะไร

ใช้ C3 (create-cloudflare — เครื่องมือสร้างโปรเจกต์ของ Cloudflare) ดาวน์โหลด starter จาก GitHub มาเป็นโฟลเดอร์ my-app และติดตั้งไลบรารีที่โปรเจกต์ต้องใช้ (dependency) ให้ — ทุกคนในห้องจึงได้โครงเดียวกัน · ความหมายของตัวเลือกท้ายคำสั่ง: --no-deploy คือยังไม่ deploy · --no-git คือยังไม่สร้าง Git เพราะเราจะทำเองในขั้น 6 · --no-agents คือไม่ให้ C3 สร้างไฟล์ AGENTS.md ของ Cloudflare มาทับไฟล์ที่โปรเจกต์มีอยู่

กลับไปโฟลเดอร์ทำงาน (ออกจาก hello-vibe) ก่อน:

cd ..
npm create cloudflare@latest my-app -- --template=werapango/workers-app-starter --no-deploy --no-git --no-agents
cd my-app

C3 จะตั้งชื่อ Worker (name ใน wrangler.jsonc) ตามชื่อโฟลเดอร์ และจัดรูปแบบไฟล์ใหม่เล็กน้อย — เป็นเรื่องปกติ · ถ้าเห็นคำเตือน npm warn install-scripts … esbuild / workerd ไม่ต้องทำอะไร · ถ้า cd my-app เข้าโฟลเดอร์ได้ แปลว่าดาวน์โหลดสำเร็จ

สร้างฐานข้อมูล D1 · 3 นาที

🎯 ทำขั้นนี้เพื่ออะไร

สร้างฐานข้อมูล D1 (ฐานข้อมูล SQL ของ Cloudflare) บนคลาวด์ชื่อ app-db และให้ wrangler เขียนการเชื่อมต่อลงใน wrangler.jsonc ให้เอง โดยตั้งชื่อที่โค้ดใช้เรียกฐานข้อมูลนี้ (binding) ว่า DB

npx wrangler d1 create app-db --binding DB --update-config

เปิดไฟล์ wrangler.jsonc ใน VS Code ถ้าเห็นส่วน "d1_databases" ที่มี database_id ของคุณ แปลว่าสำเร็จ (ถ้าไม่มี ดูปัญหาที่พบบ่อย)

Migration ในเครื่อง + ตั้งค่าครั้งแรก · 6 นาที

🎯 ทำขั้นนี้เพื่ออะไร

migration คือการรันไฟล์ SQL ในโฟลเดอร์ migrations/ เพื่อสร้างหรือแก้ตาราง · ขั้นนี้สร้างตาราง users, sessions ในฐานข้อมูลจำลองบนเครื่องของคุณ (--local) แล้วลองใช้ระบบผู้ใช้ที่ starter มีให้

npx wrangler d1 migrations apply app-db --local

ถามยืนยัน ตอบ y

npm run dev
  1. เปิด http://localhost:8787/api/health ในเบราว์เซอร์ ตอนนี้ต้องเห็น "db": "ready" (แปลว่าเชื่อมฐานข้อมูลแล้ว)
  2. เปิด http://localhost:8787 จะเจอหน้า ตั้งค่าครั้งแรก ให้สร้างบัญชี admin (ตั้งชื่อ/รหัสเอง และจำไว้ ต้องใช้ในขั้น 5)
  3. ไปที่เมนู ผู้ใช้ แล้วเพิ่มผู้ใช้ทั่วไป 1 คน
  4. กด F12 เพื่อเปิดเครื่องมือนักพัฒนาของเบราว์เซอร์ ไปที่แท็บ Network แล้วล็อกเอาต์และล็อกอินใหม่ จะเห็นคำขอ /api/auth/login ให้ดู method, status และ JSON ที่ตอบกลับ จากนั้นไปที่แท็บ Application → Cookies จะเห็น cookie ชื่อ session ที่ติ๊ก HttpOnly ไว้ (แปลว่า JavaScript ในหน้าเว็บอ่านค่านี้ไม่ได้)

ขึ้น production + สร้าง admin ทันที · 6 นาที

🎯 ทำขั้นนี้เพื่ออะไร

production คือระบบจริงบนอินเทอร์เน็ตที่คนอื่นเข้าใช้ได้ · ฐานข้อมูลบนคลาวด์เป็นคนละตัวกับฐานข้อมูลในเครื่อง จึงต้องรัน migration แบบ --remote (บนคลาวด์) ก่อน แล้วค่อยอัปโหลดโค้ดด้วย deploy

npx wrangler d1 migrations apply app-db --remote
npx wrangler deploy

อ่านผลที่ wrangler แสดง แล้วหาให้เจอ: ขนาดที่อัปโหลด (Total Upload) · ไฟล์หน้าเว็บ (assets) ที่อัปโหลดขึ้นไป · การเชื่อมฐานข้อมูล DB · URL ของแอป · Current Version ID (รหัสของเวอร์ชันที่เพิ่งขึ้น)

⚠ เปิด URL แล้วสร้าง admin ทันที

หน้าตั้งค่าครั้งแรกเปิดให้ใครก็ได้ที่รู้ URL จนกว่าจะมีผู้ใช้คนแรก — ใครเข้าก่อนได้เป็น admin นี่คือความเสี่ยงด้านความปลอดภัยจริง จึงต้องสร้าง admin ของคุณให้เร็วที่สุด

เปิด URL ของแอปในเบราว์เซอร์ แล้วสร้าง admin บน production จากนั้นเปิด URL เดียวกันจากมือถือ ถ้าล็อกอินได้ แปลว่าสำเร็จ

ปล่อยเวอร์ชัน 2 (release) แล้วย้อนกลับ (rollback) · 4 นาที

🎯 ทำขั้นนี้เพื่ออะไร

ลองเองให้เห็นว่าทุกครั้งที่ปล่อยเวอร์ชันใหม่ (release) เราย้อนกลับไปเวอร์ชันก่อนได้ (rollback) — ถ้าเวอร์ชันใหม่มีปัญหาก็ย้อนกลับได้ จึง deploy บ่อย ๆ ได้โดยไม่ต้องกังวล

ใน VS Code แก้ข้อความใน public/index.html เช่นเปลี่ยน 🚀 แอปของฉัน เป็น 🚀 แอปของฉัน v2 แล้วรันใน Git Bash ทีละคำสั่ง: deploy คือขึ้นเวอร์ชัน 2 (รีเฟรชหน้าเว็บควรเห็น v2) · deployments list คือดูรายการเวอร์ชันที่เคย deploy · rollback คือย้อนกลับไปเวอร์ชันก่อนหน้า (ถ้าถามเหตุผล พิมพ์สั้น ๆ หรือกด Enter ข้ามได้ · ถ้าถามยืนยัน ตอบ y)

npx wrangler deploy
npx wrangler deployments list
npx wrangler rollback

รีเฟรชหน้าเว็บ ถ้ากลับเป็นข้อความเดิม (ไม่มี v2) แปลว่า rollback สำเร็จ ตรวจซ้ำได้ด้วย deployments list อีกครั้ง จากนั้น deploy อีกรอบเพื่อกลับเป็น v2 แล้ว commit

npx wrangler deploy
git commit -am "lab 1: v2 title"

ส่วนที่ 3 — task (ส่งทีละข้อ แล้ว commit หลังแต่ละข้อ)

T1 โครงแอป

ทำ T1: แปลง src/index.ts เป็น Hono แยก route ไว้ใน src/routes/ เพิ่ม GET /api/health ตอบ { ok: true, db, time }
โดย db บอกสถานะฐานข้อมูล ("ready" / "no-binding" / "not-migrated"), ดัก 404 และ 500 เป็น JSON,
ตั้ง wrangler.jsonc ให้มี assets (public/) และ observability พร้อมคอมเมนต์ภาษาไทยทุกส่วน
เสร็จเมื่อ: npm run dev แล้ว /api/health ตอบ 200 และหน้า public/index.html เรียก API นี้แสดงผลได้

T2 การทดสอบ

ทำ T2: สร้าง scripts/smoke.mjs (เรียก API จริง, จำ cookie ได้แบบเบราว์เซอร์, เลือก local/production และบอกบัญชี admin ด้วยค่า url= user= pass= ต่อท้ายคำสั่ง ให้พิมพ์ได้เหมือนกันทั้ง Git Bash และ PowerShell,
ชื่อเคสขึ้นต้นด้วยรหัส AC, รายงาน ผ่าน/ไม่ผ่าน/ข้าม) และ scripts/trace.mjs (ตรวจว่า AC ตัวหนาทุกข้อใน SPEC.md
มีเคสใน smoke.mjs และทุกเคสอ้าง AC ที่มีจริง, เตือนถ้า FR ใน docs/SRS.md ไม่ถูกอ้างใน SPEC.md)
เพิ่ม npm scripts: dev, deploy, smoke, trace

👤 หลัง T2 สร้างฐานข้อมูล:

npx wrangler d1 create app-db --binding DB --update-config

T3 ฐานข้อมูลผู้ใช้ + ไลบรารี auth

ทำ T3: migration ตาราง users (username unique, password_hash, role admin/user, created_at)
และ sessions (token, user_id อ้าง users ลบตาม, expires_at) + src/lib/auth.ts:
hash ด้วย PBKDF2-SHA256 100,000 รอบ + salt สุ่ม เก็บเป็น "salt:hash", session token สุ่ม 32 ไบต์ อายุ 7 วัน,
cookie HttpOnly + SameSite=Lax (Secure เมื่อเป็น https), middleware requireAuth (ฝาก userId, username, role ใน context)
และ requireAdmin (403 ถ้าไม่ใช่ admin)

👤 หลัง T3:
