Cloudflare คืออะไร

Cloudflare เริ่มจากเป็นเครือข่ายส่งเนื้อหา (CDN) และป้องกันเว็บที่มีศูนย์ข้อมูลกระจายอยู่ทั่วโลก ต่อมาเปิดให้นักพัฒนารันโค้ดของตัวเองบนเครือข่ายนั้นได้ด้วย เรียกรวม ๆ ว่า Developer Platform ซึ่งเป็นส่วนที่หลักสูตรนี้ใช้

เรื่องเช่าเครื่อง (VPS / server)Cloudflare Workers (serverless)
ต้องดูแลอะไรระบบปฏิบัติการ อัปเดต ความปลอดภัย พอร์ต SSLเฉพาะโค้ดของเรา — แพลตฟอร์มดูแลที่เหลือ
โค้ดรันเมื่อไรเปิดเครื่องรอไว้ตลอด 24 ชม.รันเฉพาะตอนมีคำขอเข้ามา
รันที่ไหนเครื่องเดียว ที่เดียวศูนย์ข้อมูลที่ใกล้ผู้ใช้ (edge)
HTTPSตั้งค่าใบรับรองเองได้อัตโนมัติ

📖 ทำไมหลักสูตรเลือก Cloudflare (ย่อจาก ADR-01)

ข้อจำกัดของเราคือ ไม่ใช้บัตรเครดิต และใช้เครื่อง Lab ที่ไม่มีสิทธิ์ admin Workers + D1 ให้ทั้ง server ฐานข้อมูล HTTPS และ URL สาธารณะในแผนฟรี สั่งทุกอย่างผ่าน npx wrangler ได้โดยไม่ต้องติดตั้งอะไรเพิ่ม และได้ URL จริงตั้งแต่ชั่วโมงแรก — ตรงกับหลักการ “deploy เร็ว ถอยได้”

Workers: โค้ดที่รันเมื่อมีคำขอ

Worker คือโค้ด JavaScript/TypeScript ที่ Cloudflare รันทุกครั้งที่มี HTTP request เข้ามา รับ request แล้วต้องคืน response — ไม่มีเครื่องที่เปิดรอไว้ ไม่มีโปรแกรมที่ต้อง restart

// src/index.ts (ย่อ) — Hono ช่วยแยก request ไปตาม path
const app = new Hono<AppEnv>();
app.route("/api/health", health);
app.route("/api/auth", auth);
app.route("/api/users", users);
export default app;   // Cloudflare เรียก app.fetch(request, env) ให้ทุกคำขอ
ลักษณะผลต่อการเขียนโค้ด
CPU 10 ms ต่อคำขอ (Free)นับเฉพาะเวลาที่ CPU คำนวณจริง เวลารอฐานข้อมูลไม่นับ · งานที่หนักที่สุดของ starter คือ hash รหัสผ่านตอนล็อกอิน (PBKDF2 100,000 รอบ ค่าสูงสุดที่ Workers รองรับ) — ถ้าล็อกอินบน production ได้ error 1102 แปลว่าเกินเพดาน CPU
ไม่มีตัวแปรที่อยู่ข้ามคำขอแน่นอนห้ามเก็บ session หรือข้อมูลไว้ในตัวแปร global — ต้องเก็บใน D1
ไม่มี filesystemอ่าน/เขียนไฟล์แบบ Node.js ไม่ได้ · ไฟล์หน้าเว็บมาจาก Static Assets
Web API มาตรฐานใช้ fetch, crypto.subtle, Request/Response เหมือนในเบราว์เซอร์

Static Assets: หน้าเว็บที่ส่งตรงจาก edge

ไฟล์ในโฟลเดอร์ public/ ถูกอัปโหลดไปพร้อม wrangler deploy ถ้า path ที่ขอตรงกับไฟล์ (เช่น / → index.html, /app.js) Cloudflare ส่งไฟล์ให้เลยโดยไม่รัน Worker ถ้าไม่ตรงกับไฟล์ใด (เช่น /api/users) จึงส่งต่อให้ Worker

// wrangler.jsonc
"main": "src/index.ts",
"assets": { "directory": "./public" }
✅ ข้อดีที่วัดได้

คำขอไฟล์ static ฟรีและไม่จำกัดจำนวน และไม่นับรวมในโควตา 100,000 คำขอต่อวันของ Worker — โควตาถูกใช้เฉพาะคำขอ API จริง ๆ · ข้อจำกัด: ไฟล์ละไม่เกิน 25 MiB และไม่เกิน 20,000 ไฟล์ต่อเวอร์ชัน

D1: ฐานข้อมูล SQLite บน Cloudflare

D1 เป็นฐานข้อมูลแบบ SQLite ที่ Cloudflare ดูแลให้ เขียน SQL ปกติ (SELECT, INSERT, JOIN) และมี 2 ชุดเสมอ: ชุดจำลองบนเครื่องเรา กับชุดจริงบน Cloudflare

Local (--local)Remote (--remote)
อยู่ที่ไหนไฟล์ใน .wrangler/state/ บนเครื่องบน Cloudflare
ใช้กับnpm run dev · npm run smokeแอปบน workers.dev
ลบทิ้งแล้วสร้างใหม่ได้ด้วย migrationข้อมูลผู้ใช้จริงหาย — ระวัง
 
npx wrangler d1 create app-db --binding DB --update-config   # สร้างฐานข้อมูล + เขียน d1_databases ลง wrangler.jsonc
npx wrangler d1 migrations apply app-db --local               # สร้างตารางในเครื่อง
npx wrangler d1 migrations apply app-db --remote              # สร้างตารางบน production
npx wrangler d1 execute app-db --remote --command "SELECT username, role FROM users"
📖 Migration = ประวัติการเปลี่ยนโครงสร้างฐานข้อมูล

ไฟล์ใน migrations/ ถูกรันตามลำดับเลข และ D1 จดไว้ว่ารันไฟล์ไหนไปแล้ว — รันซ้ำก็ไม่ทำซ้ำ เปลี่ยนโครงสร้างต้องเพิ่มไฟล์ใหม่เสมอ ห้ามแก้ไฟล์เก่าที่รันบน remote ไปแล้ว

⚠ rollback โค้ด ≠ rollback ฐานข้อมูล

wrangler rollback ย้อนเฉพาะโค้ด · ถ้าต้องย้อนข้อมูลจริง D1 มี Time Travel ย้อนฐานข้อมูลไปจุดเวลาใดก็ได้ในช่วง 7 วัน (Free) ด้วย npx wrangler d1 time-travel restore — เป็นทางหนีไฟ ไม่ใช่เครื่องมือประจำวัน

Binding: Worker คุยกับ D1 โดยไม่มีรหัสผ่าน

ฐานข้อมูลทั่วไปต้องมี connection string ที่มีรหัสผ่าน ซึ่งเสี่ยงหลุด Cloudflare ใช้ binding แทน: ประกาศใน wrangler.jsonc ว่าชื่อ DB ผูกกับฐานข้อมูลไหน แล้วในโค้ดเรียก c.env.DB ได้เลย ไม่มีรหัสผ่านในโค้ดหรือใน git

// wrangler.jsonc — d1 create --update-config เขียนให้
"d1_databases": [{ "binding": "DB", "database_name": "app-db", "database_id": "…" }]

// src/routes/users.ts — ใช้ผ่าน binding เสมอ และใช้ ? กัน SQL injection
const row = await c.env.DB.prepare("SELECT id, username, role FROM users WHERE id = ?").bind(id).first();

/api/health ของ starter บอกสถานะ binding ได้ 3 แบบ: no-binding (ยังไม่ได้ d1 create) → not-migrated (ยังไม่มีตาราง) → ready

workers.dev, Versions และ rollback

  • workers.dev — ทุกบัญชีได้ subdomain ฟรี 1 ชื่อ (ตั้งตอน deploy ครั้งแรก หรือใน Dashboard) แต่ละ Worker ได้ URL https://<ชื่อ Worker>.<subdomain>.workers.dev พร้อม HTTPS — Cloudflare ระบุว่าเหมาะกับงานส่วนตัวหรือโปรเจกต์ทดลอง ระบบจริงขององค์กรควรใช้โดเมนของตัวเอง
  • Versions — ทุก wrangler deploy สร้างเวอร์ชันใหม่ เวอร์ชันเก่าเก็บไว้ (Free: 30 วัน)
  • rollback — สลับกลับไปใช้เวอร์ชันก่อนได้ทันทีโดยไม่ต้อง build ใหม่
npx wrangler deployments list   # ดูประวัติการ deploy
npx wrangler rollback           # กลับไปเวอร์ชันก่อนหน้า
npx wrangler delete             # ลบ Worker ทั้งตัว (ใช้ตอนเก็บกวาด)

ทบทวน + เชื่อมกับ Lab
