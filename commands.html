อ้างอิง

คำสั่งที่ใช้ทั้งวัน จัดตาม phase ของ SDLC

ทุกคำสั่งในหน้านี้ คนพิมพ์เองใน Git Bash — agent มีหน้าที่บอกว่าต้องรันอะไร แต่ไม่รันเอง ชื่อที่ใช้ทั้งวัน: โฟลเดอร์ my-app · ฐานข้อมูล app-db · binding DB

⚠ ทำไม agent ห้ามรันคำสั่งเหล่านี้

AGENTS.md กติกาข้อ 2 ห้าม agent รัน wrangler, npm install, git เพราะ (1) คำสั่งพวกนี้กระทบของจริง เช่น deploy ทับ production หรือรัน migration กับฐานข้อมูลบนคลาวด์ — คนต้องเป็นผู้ตัดสินใจ (2) ผลลัพธ์ของคำสั่งยาวมาก ถ้า agent อ่านเองจะเปลือง token และ (3) คนที่พิมพ์คำสั่งเองจะเข้าใจระบบของตัวเอง

npx wrangler logoutลบสิทธิ์บัญชีคุณออกจากเครื่องก่อนออกจากห้อง Lab ทุกครั้งแอปที่ deploy แล้วยังทำงานปกติ

พัฒนาในเครื่อง (local)

คำสั่งทำอะไรใช้เมื่อไรกระทบอะไร
npm run dev (= npx wrangler dev)รันเซิร์ฟเวอร์จำลองที่ http://localhost:8787 แก้ไฟล์แล้วโหลดใหม่เองตลอดการพัฒนา (เปิดค้างไว้อีกหน้าต่าง)เครื่องเท่านั้น · ใช้ฐานข้อมูล local · หยุดด้วย Ctrl+C
npx wrangler dev --port 8788รันที่ port อื่นport 8787 ชนเครื่องเท่านั้น

ฐานข้อมูลและ migration

คำสั่งทำอะไรใช้เมื่อไรกระทบอะไร
npx wrangler d1 create app-db --binding DB --update-configสร้างฐานข้อมูล D1 บนคลาวด์ + เพิ่ม d1_databases ใน wrangler.jsonc ให้เองLab 1b (ครั้งเดียว)สร้างฐานข้อมูลบนบัญชีคุณ (free plan)
npx wrangler d1 listดูรายชื่อฐานข้อมูลและ database_idต้องการ id ไปใส่ wrangler.jsonc (เช่น หลังคัดลอก checkpoint)อ่านอย่างเดียว
npx wrangler d1 migrations create app-db ชื่อสร้างไฟล์ migrations/NNNN_ชื่อ.sql เปล่าที่เลขถัดไปเมื่อจะเปลี่ยน schema เอง (agent มักสร้างไฟล์ให้แล้ว)สร้างไฟล์ในเครื่อง
npx wrangler d1 migrations apply app-db --localรัน migration ที่ยังไม่เคยรันกับฐานข้อมูลในเครื่องหลังทุก task ที่มี migration ใหม่ฐานข้อมูลใน .wrangler/ · ถามยืนยัน ตอบ y
npx wrangler d1 migrations apply app-db --remoteรัน migration กับฐานข้อมูลบนคลาวด์ก่อน deploy ทุกครั้งที่มี migration ใหม่production — migration เดินหน้าอย่างเดียว ย้อนไม่ได้
npx wrangler d1 migrations list app-db --localดู migration ที่ยังไม่ได้รันสงสัยว่ารันครบหรือยังอ่านอย่างเดียว
npx wrangler d1 execute app-db --local --command "SELECT …"รัน SQL ตรง ๆ กับฐานข้อมูลในเครื่องตรวจข้อมูลระวัง: ถ้าเป็น UPDATE/DELETE ข้อมูลเปลี่ยนจริง
npx wrangler d1 execute app-db --remote --command "SELECT username, role, password_hash FROM users"ดูข้อมูลบน productionLab 4 เช็กลิสต์ข้อ 2 (inspection)production — ใช้ SELECT เท่านั้น

ทดสอบ

คำสั่งทำอะไรใช้เมื่อไรกระทบอะไร
npm run smokeเรียก API จริงที่ localhost แล้วเช็กผลตาม AC (ต้องเปิด npm run dev ไว้)หลังทุก taskสร้างผู้ใช้/ข้อมูลชั่วคราวแล้วลบทิ้งเอง · ถ้าฐานข้อมูลว่างจะสร้าง admin admin / admin-pass-1234
SMOKE_ADMIN_USER=admin SMOKE_ADMIN_PASS=รหัสของคุณ npm run smokeบอก smoke test ว่า admin ของคุณคือใครเมื่อสร้าง admin เองแล้ว (ไม่บอก = เคสที่ต้องใช้ admin จะถูกข้าม)เหมือนข้างบน
BASE_URL=https://my-app.….workers.dev SMOKE_ADMIN_USER=… SMOKE_ADMIN_PASS=… npm run smokeรัน smoke test ชุดเดียวกันกับ productionหลัง deployสร้างแล้วลบข้อมูลชั่วคราวบน production
npm run traceตรวจว่า AC ทุกข้อใน SPEC.md มีเคสใน smoke และ FR ทุกข้อใน docs/SRS.md ถูกอ้างใน SPECหลังแก้ spec หรือหลังทุก taskอ่านไฟล์อย่างเดียว ไม่ต้องเปิด dev

PowerShell: $env:BASE_URL="https://..."; $env:SMOKE_ADMIN_USER="admin"; $env:SMOKE_ADMIN_PASS="..."; npm run smoke

Deploy / release

คำสั่งทำอะไรใช้เมื่อไรกระทบอะไร
npx wrangler deploybundle โค้ด + อัปโหลดหน้าเว็บ ขึ้น Cloudflare ได้เวอร์ชันใหม่จบ Lab 1b · จบ Lab 3 · หลังแก้ใน Lab 4production ผู้ใช้เห็นทันที

🎯 ลำดับ release ที่ถูกต้อง

npm run smoke + npm run trace ผ่านใน local → git commit → d1 migrations apply app-db --remote → wrangler deploy → smoke กับ production — migration ต้องมาก่อน deploy ไม่งั้นโค้ดใหม่จะหาตารางไม่เจอ

Git

คำสั่งทำอะไรใช้เมื่อไร
git initเริ่มเก็บประวัติในโฟลเดอร์นี้Lab 1b ครั้งเดียว
git config user.name "ชื่อ" · git config user.email "อีเมล"ตั้งชื่อผู้ commit เฉพาะโปรเจกต์นี้ (ไม่ใช้ --global เพราะเครื่องส่วนกลาง)หลัง git init
git statusดูว่ามีไฟล์ไหนเปลี่ยนก่อน commit
git diffดูทีละบรรทัดว่าเปลี่ยนอะไร — code review ยุค agentหลังทุก task · หลังคัดลอก baseline (เทียบ spec)
git add . && git commit -m "ข้อความ"บันทึก checkpointหลังทุก task ที่ตรวจผ่าน
git restore .ทิ้งการแก้ไขที่ยังไม่ commit ทั้งหมดagent ทำพังหรือทำเกิน task
git log --oneline --decorateดูประวัติ commit และ tagretro
