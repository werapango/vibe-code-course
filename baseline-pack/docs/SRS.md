# SRS — Software Requirements Specification: ระบบจองรถส่วนกลาง (ฉบับอ้างอิง / baseline)

> เอกสารความต้องการฉบับเต็มสำหรับ **คน** — ทุกข้อบอกที่มาได้: **B#** = ย่อหน้าในโจทย์จากผู้ใช้ · **Q#** = คำตอบของเจ้าของโจทย์ (§8)
> ฉบับย่อสำหรับ agent อยู่ที่ `SPEC.md`

## 1. บทนำ
- **วัตถุประสงค์ของระบบ:** ให้พนักงานจองรถส่วนกลางได้เองจากมือถือ เห็นว่ารถว่างไหม และป้องกันการจองซ้อนเวลาและการจองเกินที่นั่ง (B2, B3)
- **ขอบเขต:** Release 1 ทำ FR ระดับ "ต้องมี" ทั้งหมด (§4) · ไม่ทำระบบอนุมัติและสถานะรถซ่อม (§7)
- **เอกสารอ้างอิง:** โจทย์จากผู้ใช้ "บันทึกจากหัวหน้างานยานพาหนะ" (B1–B7) · บันทึกการคุยกับเจ้าของโจทย์ (Q1–Q12)

## 2. ผู้มีส่วนได้ส่วนเสีย (Stakeholders) และผู้ใช้
| กลุ่ม | บทบาท / สิ่งที่ต้องการ | ใช้ระบบไหม |
|---|---|---|
| หัวหน้างานยานพาหนะ | เจ้าของโจทย์ · อยากให้การจองไม่ชนกัน ลดงานรับโทรศัพท์ | ใช้ (role admin) |
| เจ้าหน้าที่งานยานพาหนะ | ดูแลข้อมูลรถ สร้างบัญชีพนักงาน | ใช้ (role admin) |
| พนักงาน | จองรถเองจากมือถือ รู้ว่ารถว่างไหม | ใช้ (role user) |
| ผู้บริหาร / ฝ่ายการเงิน | ไม่มีงบ — ระบบต้องไม่มีค่าใช้จ่าย (B7) | ไม่ใช้ แต่ได้รับผล |

## 3. Use Cases
### 3.1 รายการ use case
| รหัส | ชื่อ | actor |
|---|---|---|
| UC-01 | จัดการข้อมูลรถ | งานยานพาหนะ |
| UC-02 | จองรถ | พนักงาน |
| UC-03 | ดูและยกเลิกการจองของตัวเอง | พนักงาน |
| UC-04 | ดูตารางรถรายวัน | พนักงาน |
| UC-05 | จัดการบัญชีพนักงาน | งานยานพาหนะ (มีใน starter) |

### 3.2 รายละเอียด use case หลัก
**UC-02 จองรถ**
- **Actor:** พนักงาน
- **เงื่อนไขก่อนเริ่ม:** ล็อกอินแล้ว · มีรถในระบบอย่างน้อย 1 คัน
- **ขั้นตอนหลัก:**
  1. พนักงานเลือกรถ และดูตารางของรถคันนั้นในวันที่ต้องการ (UC-04)
  2. กรอกเวลาเริ่ม เวลาจบ ปลายทาง จำนวนผู้โดยสาร และเหตุผล (ไม่บังคับ)
  3. ระบบตรวจกติกา: ไม่ย้อนหลัง · ผู้โดยสารไม่เกินที่นั่ง · ไม่ซ้อนเวลากับการจองเดิมของรถคันนั้น
  4. ระบบบันทึกการจอง และแสดงในรายการ "การจองของฉัน"
- **ทางเลือก / กรณีผิดปกติ:**
  - 3a. เวลาซ้อน → ระบบปฏิเสธ แจ้ง "รถคันนี้ไม่ว่างในช่วงเวลานั้น" → กลับไปขั้น 1
  - 3b. ผู้โดยสารเกินที่นั่ง → ระบบปฏิเสธ แจ้งจำนวนที่นั่ง → เลือกรถคันใหญ่กว่า
  - 3c. เวลาเริ่มอยู่ในอดีต หรือเริ่มไม่ก่อนจบ → ระบบปฏิเสธ
- **ผลลัพธ์:** การจองถูกบันทึก ช่วงเวลานั้นแสดงว่า "ไม่ว่าง" ในตารางของรถ

| รหัส | ระบบต้อง... | ที่มา | ความสำคัญ | use case |
|---|---|---|---|---|

| FR-02 | ให้ผู้ใช้ที่ล็อกอินดูรายการรถทั้งหมด | B3 | ต้องมี | UC-02 |
| FR-03 | ให้ผู้ใช้จองรถ โดยระบุรถ เวลาเริ่ม เวลาจบ ปลายทาง จำนวนผู้โดยสาร (บังคับ) และเหตุผล (ไม่บังคับ) | B3, Q4 | ต้องมี | UC-02 |
| FR-04 | ปฏิเสธการจองรถคันเดียวกันที่ช่วงเวลาทับกัน — ต่อคิวพอดีไม่นับว่าทับ | B2, B3, Q1 | ต้องมี | UC-02 |
| FR-05 | ปฏิเสธการจองที่เวลาเริ่มอยู่ในอดีต | Q2 | ต้องมี | UC-02 |
| FR-06 | ปฏิเสธการจองที่จำนวนผู้โดยสารเกินจำนวนที่นั่งของรถ | B2, Q5 | ต้องมี | UC-02 |
| FR-07 | แสดงรายการการจองของผู้ใช้คนนั้นเท่านั้น | B3, B5 | ต้องมี | UC-03 |
| FR-08 | ให้ผู้ใช้ยกเลิกการจองของตัวเองได้ และยกเลิกของคนอื่นไม่ได้ | B3, B5 | ต้องมี | UC-03 |
| FR-09 | แสดงตารางของรถแต่ละคันรายวัน เห็นเฉพาะช่วงเวลาที่ไม่ว่าง ไม่เห็นผู้จอง | B2, B3, Q6 | ต้องมี | UC-04 |
| FR-10 | ให้ admin สร้างและจัดการบัญชีพนักงาน (พนักงานสมัครเองไม่ได้) | B4, Q10 | ต้องมี | UC-05 |

| FR-12 | ให้ยกเลิกได้เฉพาะก่อนเวลาเริ่มของการจอง | Q7 | ควรมี (Release 2) | UC-03 |
| FR-13 | ให้ admin ดูการจองทั้งหมดพร้อมชื่อผู้จอง | Q6 | ควรมี (Release 2) | – |
| FR-14 | มีขั้นตอนให้หัวหน้าอนุมัติการจอง | B6, Q3 | ยังไม่ทำ | – |

## 5. Non-functional Requirements (NFR)
| รหัส | ด้าน | เกณฑ์ที่วัดได้ | วิธีตรวจ | ที่มา |
|---|---|---|---|---|
| NFR-01 | ใช้งาน | ใช้ทุกหน้าได้บนจอกว้าง 375px โดยไม่มี scroll แนวนอน | สาธิต (demonstration) | B3, Q8 |
| NFR-02 | ใช้งาน | ผู้ใช้ที่เคยใช้แล้วจองเสร็จภายใน 1 นาที | สาธิต + จับเวลา | Q8 |
| NFR-03 | ความปลอดภัย | รหัสผ่านเก็บเป็น hash + salt ไม่มีรหัสจริงในฐานข้อมูล | ตรวจ (inspection) | B5 (starter) |
| NFR-04 | ความปลอดภัย | ผู้ใช้เห็น/ยกเลิกการจองของคนอื่นไม่ได้ | ทดสอบ (AC-3.1, AC-3.3) | B5 |
| NFR-05 | ค่าใช้จ่าย | ใช้เฉพาะบริการฟรีที่ไม่ต้องผูกบัตร | ตรวจ (inspection) | B7 |
| NFR-06 | ความถูกต้อง | เวลาเป็นเวลาไทย รูปแบบ `YYYY-MM-DDTHH:MM` ทั้งระบบ | ทดสอบ (AC-2.5) + ตรวจข้อมูล | Q11 |

> **วิธีตรวจ 4 แบบ (verification methods):** ทดสอบ (test) · สาธิต (demonstration) · ตรวจ (inspection) · วิเคราะห์ (analysis) — ไม่ใช่ทุก requirement ที่ตรวจด้วย test อัตโนมัติได้ แต่ทุกข้อต้องมีวิธีตรวจ

## 6. ข้อจำกัดที่ยืนยันแล้ว (Constraints)
- ใช้ Cloudflare Workers + D1 free plan (B7) — รายละเอียดการตัดสินใจใน `docs/DESIGN.md` ADR-01
- ใช้ระบบผู้ใช้/เข้าสู่ระบบที่มีใน starter (FR-10)
- จองได้นานเท่าไรก็ได้ ไม่จำกัดจำนวนชั่วโมง (Q12)

## 7. นอกขอบเขต (Out of Scope) ของ Release 1
- FR-11, FR-12, FR-13 (Release 2) · FR-14 การอนุมัติ · FR-15 สถานะรถซ่อม
- การแจ้งเตือนทางอีเมล/LINE · รายงานสถิติการใช้รถ · รีเซ็ตรหัสผ่านด้วยตัวเอง

## 8. คำถามที่ถามเจ้าของโจทย์ และคำตอบ
| # | คำถาม | คำตอบ |
|---|---|---|
| Q1 | "ห้ามจองชน" — คืนรถ 12:00 แล้วอีกคนรับ 12:00 ได้ไหม | ได้ ต่อคิวพอดีไม่นับว่าชน |
| Q2 | จองล่วงหน้าได้นานแค่ไหน · จองย้อนหลังได้ไหม | ห้ามจองย้อนหลังเด็ดขาด · ล่วงหน้าไม่เกิน 30 วัน (ทำรอบหน้าได้) |
| Q3 | ต้องมีการอนุมัติในรอบนี้ไหม | ยังไม่ต้อง ไว้คุยกันรอบหน้า |
| Q4 | ตอนจองต้องกรอกอะไรบ้าง | รถ เวลาเริ่ม–จบ ปลายทาง จำนวนคน (บังคับ) · เหตุผล (ไม่บังคับ) |
| Q5 | "นั่งไม่พอ" ต้องให้ระบบกันไหม | ต้องกัน คนเกินที่นั่งห้ามจอง |
| Q6 | ตอนดูว่ารถว่าง ต้องเห็นว่าใครจองไหม | พนักงานเห็นแค่ช่วงเวลาที่ไม่ว่างก็พอ · งานยานพาหนะอยากเห็นทั้งหมดพร้อมชื่อ (รอบหน้าได้) |
| Q7 | ยกเลิกได้ถึงเมื่อไร | ควรได้แค่ก่อนเวลาเริ่ม (รอบหน้าได้ ตอนนี้ให้ยกเลิกได้ก่อน) |
| Q8 | "ใช้บนมือถือ" หมายถึงอย่างไร | มือถือทั่วไปจอเล็ก · จองให้เสร็จได้ในไม่เกิน 1 นาที |
| Q9 | ปลดรถเก่า = ลบออกจากระบบ? การจองเดิมล่ะ | ลบได้ การจองของรถคันนั้นหายไปด้วยก็ได้ · สถานะ "ซ่อม" อยากได้ภายหลัง |
| Q10 | พนักงานสมัครเองได้ไหม | ไม่ได้ งานยานพาหนะสร้างบัญชีให้ |
| Q11 | เวลาในระบบเป็นเวลาอะไร | เวลาไทย |
| Q12 | จองนานสุดกี่ชั่วโมง | ไม่จำกัด บางทีไปต่างจังหวัดหลายวัน |
