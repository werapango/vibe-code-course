# SPEC — ระบบจองรถส่วนกลาง (ฉบับอ้างอิง / baseline)

> **SPEC.md = ข้อกำหนดฉบับย่อสำหรับ agent** (ฉบับเต็มสำหรับคนอยู่ใน `docs/SRS.md` และ `docs/DESIGN.md`)
> agent อ่านไฟล์นี้แทนการแปะ prompt ยาว ๆ — spec ชัด = prompt สั้น = ประหยัด token
>
> กติกาของ AC (acceptance criteria):
> - เขียนแบบ **Given / When / Then** · 1 ข้อ = ตรวจได้ 1 เรื่อง · มีผลที่คาดหวังเป็นรูปธรรม (status, ข้อมูล)
> - รหัส AC เขียนเป็น**ตัวหนา**แบบในส่วน starter ด้านล่าง — `npm run trace` นับเฉพาะรหัสตัวหนาและตรวจว่าทุก AC มีเคสทดสอบ
> - อ้างที่มาจาก SRS ในวงเล็บ เช่น `(FR-03)` — ทำให้ตามรอยได้ว่า AC นี้มาจากความต้องการข้อไหน

## 1. เป้าหมาย (สรุปจาก SRS)
พนักงานจองรถส่วนกลางได้เองจากมือถือ เห็นว่ารถคันไหนว่าง และระบบไม่ยอมให้จองซ้อนเวลาหรือจองเกินที่นั่ง — แทนการจองผ่านกลุ่ม LINE และสมุด (SRS §1)

## 2. คำศัพท์ของโดเมน
> นิยามคำที่อาจเข้าใจไม่ตรงกัน — ถ้าคนกับ agent เข้าใจคำเดียวกันต่างกัน ระบบจะผิดแบบเงียบ ๆ

| คำ | ความหมายในระบบนี้ |
|---|---|
| ผู้ใช้ | บัญชีที่ล็อกอินได้ มี role เป็น `admin` หรือ `user` |
| รถ | รถส่วนกลางของหน่วยงาน 1 คัน ระบุด้วยทะเบียน (ไม่ซ้ำ) |
| การจอง | การขอใช้รถ 1 คัน ในช่วงเวลา [เริ่ม, จบ) ของผู้ใช้ 1 คน |
| ซ้อนเวลา | การจองรถ**คันเดียวกัน**ที่ช่วงเวลาทับกันอย่างน้อย 1 นาที — ต่อคิวพอดี (จบ 12:00 / เริ่ม 12:00) **ไม่นับ** (Q1) |
| เวลา | เวลาไทย รูปแบบ `YYYY-MM-DDTHH:MM` (Q11) |
| งานยานพาหนะ | ผู้ใช้ role `admin` |
| พนักงาน | ผู้ใช้ role `user` |

## 3. User Stories + Acceptance Criteria

### ✅ ส่วนที่ starter มีให้แล้ว (ตัวอย่าง spec ที่ตรวจสอบได้ — ห้ามลบ)

#### US-0 ตรวจสถานะระบบ
ในฐานะผู้ดูแลระบบ ฉันต้องการเช็กว่าเซิร์ฟเวอร์และฐานข้อมูลพร้อม เพื่อรู้ว่าปัญหาอยู่ที่ระบบหรือที่เครือข่าย
- **AC-0.1** Given เซิร์ฟเวอร์ทำงานและรัน migration แล้ว When `GET /api/health` Then ได้ 200 `{ ok: true, db: "ready" }`

#### US-A1 ตั้งค่าครั้งแรก
ในฐานะผู้ติดตั้งระบบ ฉันต้องการสร้างผู้ดูแลระบบคนแรกจากหน้าเว็บ เพื่อเริ่มใช้งานได้โดยไม่ต้องแก้ฐานข้อมูลเอง
- **AC-A1.1** Given ระบบยังไม่มีผู้ใช้ When `POST /api/auth/setup` ด้วยชื่อและรหัสที่ถูกกติกา Then ได้ 201, ผู้ใช้นั้นเป็น `admin` และล็อกอินอยู่ทันที
- **AC-A1.2** Given ระบบมีผู้ใช้อย่างน้อย 1 คน When `POST /api/auth/setup` Then ได้ 409 (ตั้งค่าซ้ำไม่ได้)

#### US-A2 เข้าสู่ระบบ / ออกจากระบบ
ในฐานะผู้ใช้ ฉันต้องการเข้าสู่ระบบด้วยชื่อและรหัสผ่าน เพื่อใช้งานในนามของตัวเอง
- **AC-A2.1** Given ชื่อและรหัสถูก When `POST /api/auth/login` Then ได้ 200 และ cookie `session` แบบ HttpOnly
- **AC-A2.2** Given รหัสผิด หรือไม่มีชื่อนี้ When ล็อกอิน Then ได้ 401 ด้วย**ข้อความเดียวกัน**ทั้งสองกรณี
- **AC-A2.3** Given ไม่ได้ล็อกอิน When `GET /api/auth/me` Then ได้ 401
- **AC-A2.4** Given ล็อกอินอยู่ When `POST /api/auth/logout` Then session เดิมใช้ไม่ได้อีก (`/api/auth/me` ได้ 401)

#### US-A3 เปลี่ยนรหัสผ่านของตัวเอง
ในฐานะผู้ใช้ ฉันต้องการเปลี่ยนรหัสผ่านเอง เพื่อดูแลความปลอดภัยของบัญชี
- **AC-A3.1** Given ใส่รหัสเดิมถูก และรหัสใหม่ยาว 8–100 ตัว When `PUT /api/auth/password` Then ได้ 200 และล็อกอินด้วยรหัสใหม่ได้
- **AC-A3.2** Given ใส่รหัสเดิมผิด When เปลี่ยนรหัส Then ได้ 400 และรหัสไม่เปลี่ยน

#### US-A4 จัดการผู้ใช้ (admin)
ในฐานะผู้ดูแลระบบ ฉันต้องการเพิ่ม แก้ role ตั้งรหัสใหม่ และลบผู้ใช้ เพื่อควบคุมว่าใครเข้าระบบได้
- **AC-A4.1** Given ผู้ใช้ role `user` When เรียก `/api/users` ใด ๆ Then ได้ 403
- **AC-A4.2** Given admin When `POST /api/users` (ชื่อ, รหัส, role ไม่บังคับ) Then ได้ 201, role เริ่มต้นเป็น `user` และคำตอบไม่มี `password_hash`
- **AC-A4.3** Given มีชื่อผู้ใช้นี้แล้ว When เพิ่มชื่อซ้ำ Then ได้ 409
- **AC-A4.4** Given admin ตั้งรหัสใหม่ให้ผู้ใช้ X When X ใช้ session เดิม Then ได้ 401 และ X ล็อกอินด้วยรหัสใหม่ได้
- **AC-A4.5** Given admin When ลบบัญชีตัวเอง Then ได้ 409 · When ลบผู้ใช้อื่น Then ได้ 200
- **AC-A4.6** Given มี admin เหลือคนเดียว When เปลี่ยน role ของเขาเป็น `user` Then ได้ 409

### 🚗 ส่วนของโจทย์: ระบบจองรถ (Release 1 — เฉพาะ FR ระดับ "ต้องมี")

#### US-1 จัดการรถส่วนกลาง (FR-01, FR-02)
ในฐานะงานยานพาหนะ (admin) ฉันต้องการเพิ่ม แก้ และลบข้อมูลรถ เพื่อให้พนักงานเลือกรถที่มีอยู่จริงตอนจอง
- **AC-1.1** Given admin When `POST /api/cars` ด้วยทะเบียน ชื่อ/รุ่น และที่นั่ง > 0 Then ได้ 201 และข้อมูลรถ
- **AC-1.2** Given มีรถทะเบียน X แล้ว When เพิ่มรถทะเบียน X อีก Then ได้ 409 "ทะเบียนนี้มีอยู่แล้ว"
- **AC-1.3** Given ที่นั่ง ≤ 0 หรือไม่กรอกทะเบียน/ชื่อ When เพิ่มรถ Then ได้ 400
- **AC-1.4** Given ผู้ใช้ role `user` When เพิ่ม/แก้/ลบรถ Then ได้ 403
- **AC-1.5** Given ล็อกอินแล้ว (role ใดก็ได้) When `GET /api/cars` Then ได้รายการรถทั้งหมด · ไม่ล็อกอินได้ 401
- **AC-1.6** Given admin When `PUT /api/cars/:id` Then ข้อมูลเปลี่ยน · id ที่ไม่มีได้ 404 · ลบรถแล้วการจองของรถคันนั้นถูกลบตาม (Q9)

#### US-2 จองรถ (FR-03, FR-04, FR-05, FR-06)
ในฐานะพนักงาน ฉันต้องการจองรถตามช่วงเวลา เพื่อมั่นใจว่ามีรถและที่นั่งพอสำหรับการเดินทาง
- **AC-2.1** Given รถว่าง When `POST /api/bookings` ด้วย รถ, เวลาเริ่ม, เวลาจบ, ปลายทาง, จำนวนผู้โดยสาร (เหตุผลไม่บังคับ) Then ได้ 201
- **AC-2.2** Given รถ A ถูกจอง 10:00–12:00 When จองรถ A ช่วงที่ทับกัน (ตัวอย่าง #1–#5) Then ได้ 409 "รถคันนี้ไม่ว่างในช่วงเวลานั้น"
- **AC-2.3** Given รถ A ถูกจอง 10:00–12:00 When จองต่อคิวพอดี หรือจองคนละคัน (ตัวอย่าง #6–#8) Then ได้ 201
- **AC-2.4** Given เวลาเริ่ม ≥ เวลาจบ หรือรูปแบบเวลาไม่ใช่ `YYYY-MM-DDTHH:MM` When จอง Then ได้ 400
- **AC-2.5** Given เวลาเริ่มอยู่ก่อนเวลาปัจจุบัน (เวลาไทย) When จอง Then ได้ 400 "จองย้อนหลังไม่ได้"
- **AC-2.6** Given รถมี N ที่นั่ง When จองด้วยผู้โดยสาร > N Then ได้ 400 · ผู้โดยสาร = N พอดี Then ได้ 201
- **AC-2.7** Given ไม่ได้ล็อกอิน When เรียก `/api/bookings` ใด ๆ Then ได้ 401

**ตารางตัวอย่าง — กติกาเวลาซ้อน** (มีการจองเดิม: รถ A 10:00–12:00 · ช่วงเวลาแบบ [เริ่ม, จบ) — Q1)

| # | จองใหม่ | ผลที่คาดหวัง | เหตุผล | AC |
|---|---|---|---|---|
| 1 | รถ A 11:00–13:00 | 409 | ทับช่วงท้าย | AC-2.2 |
| 2 | รถ A 09:00–11:00 | 409 | ทับช่วงต้น | AC-2.2 |
| 3 | รถ A 10:30–11:30 | 409 | อยู่ข้างใน | AC-2.2 |
| 4 | รถ A 09:00–13:00 | 409 | คลุมทั้งช่วง | AC-2.2 |
| 5 | รถ A 10:00–12:00 | 409 | ช่วงเดียวกันเป๊ะ | AC-2.2 |
| 6 | รถ A 12:00–14:00 | 201 | ต่อคิวพอดีด้านหลัง | AC-2.3 |
| 7 | รถ A 08:00–10:00 | 201 | ต่อคิวพอดีด้านหน้า | AC-2.3 |
| 8 | รถ B 10:00–12:00 | 201 | คนละคัน | AC-2.3 |

#### US-3 การจองของฉัน (FR-07, FR-08)
ในฐานะพนักงาน ฉันต้องการดูและยกเลิกการจองของตัวเอง เพื่อคืนรถให้คนอื่นเมื่อไม่ได้ไปแล้ว
- **AC-3.1** Given A และ B ต่างคนต่างจอง When A เรียก `GET /api/bookings` Then เห็นเฉพาะการจองของ A
- **AC-3.2** Given การจองของฉัน When `DELETE /api/bookings/:id` Then ได้ 200 และการจองหายไป
- **AC-3.3** Given การจองของคนอื่น When สั่งยกเลิก Then ได้ 404 และการจองนั้นยังอยู่

#### US-4 ดูว่ารถว่างไหม (FR-09)
ในฐานะพนักงาน ฉันต้องการดูตารางของรถแต่ละคันรายวัน เพื่อเลือกช่วงเวลาที่ว่างก่อนจอง
- **AC-4.1** Given มีการจองในวันนั้น When `GET /api/cars/:id/schedule?date=YYYY-MM-DD` Then ได้รายการช่วงเวลา (`start_at`, `end_at`) ที่ทับวันนั้น **โดยไม่มีข้อมูลผู้จอง** (Q6)
- **AC-4.2** Given วันที่รูปแบบผิด When เรียกตาราง Then ได้ 400

> **FR-10** (admin สร้างบัญชีพนักงาน) ใช้ของ starter: US-A4 ด้านบน
> **ตรวจด้วยวิธีอื่น (ไม่ใช่ smoke test):** NFR-01, NFR-02 ด้วยการสาธิต (demonstration) · NFR-03, NFR-05, NFR-06 ด้วยการตรวจ (inspection) — ดู §6

## 4. Data Model
| ตาราง | คอลัมน์ | กติกา (constraint) |
|---|---|---|
| users | id, username, password_hash, role, created_at | username UNIQUE · role ∈ {admin, user} · เก็บ hash ไม่เก็บรหัสจริง |
| sessions | token, user_id, expires_at | token สุ่ม 32 ไบต์ · หมดอายุ 7 วัน · ลบผู้ใช้ = ลบ session |
| cars | id, plate, name, seats, created_at | plate UNIQUE · seats > 0 |
| bookings | id, car_id, user_id, start_at, end_at, destination, passengers, purpose, created_at | car_id → cars (ลบรถ = ลบการจอง) · user_id → users · start_at < end_at · passengers > 0 |

ความสัมพันธ์: รถ 1 คัน มีได้หลายการจอง · ผู้ใช้ 1 คน มีได้หลายการจอง

## 5. API Contract
| Method | Path | สิทธิ์ | รับ (body) | ตอบสำเร็จ | ตอบ error |
|---|---|---|---|---|---|
| GET | /api/health | ทุกคน | – | 200 `{ok, db, time}` | – |
| GET | /api/auth/setup | ทุกคน | – | 200 `{needsSetup}` | – |
| POST | /api/auth/setup | ทุกคน (ครั้งแรก) | `{username,password}` | 201 `user` + cookie | 400, 409 |
| POST | /api/auth/login | ทุกคน | `{username,password}` | 200 `user` + cookie | 400, 401 |
| POST | /api/auth/logout | ทุกคน | – | 200 | – |
| GET | /api/auth/me | ล็อกอิน | – | 200 `{id,username,role}` | 401 |
| PUT | /api/auth/password | ล็อกอิน | `{current_password,new_password}` | 200 | 400, 401 |
| GET | /api/users | admin | – | 200 `[user]` | 401, 403 |
| POST | /api/users | admin | `{username,password,role?}` | 201 `user` | 400, 401, 403, 409 |
| PUT | /api/users/:id | admin | `{role?,password?}` | 200 `user` | 400, 401, 403, 404, 409 |
| DELETE | /api/users/:id | admin | – | 200 | 401, 403, 404, 409 |
| GET | /api/cars | ล็อกอิน | – | 200 `[car]` | 401 |
| POST | /api/cars | admin | `{plate,name,seats}` | 201 `car` | 400, 401, 403, 409 |
| PUT | /api/cars/:id | admin | `{plate,name,seats}` | 200 `car` | 400, 401, 403, 404, 409 |
| DELETE | /api/cars/:id | admin | – | 200 | 401, 403, 404 |
| GET | /api/cars/:id/schedule?date= | ล็อกอิน | – | 200 `[{start_at,end_at}]` | 400, 401, 404 |
| GET | /api/bookings | ล็อกอิน | – | 200 `[booking]` ของฉัน | 401 |
| POST | /api/bookings | ล็อกอิน | `{car_id,start_at,end_at,destination,passengers,purpose?}` | 201 `booking` | 400, 401, 404, 409 |
| DELETE | /api/bookings/:id | ล็อกอิน (เจ้าของ) | – | 200 | 401, 404 |

## 6. Non-functional Requirements (ต้องวัดได้)
| รหัส | เรื่อง | เกณฑ์ที่วัดได้ | ตรวจอย่างไร |
|---|---|---|---|
| NFR-S1 | ความปลอดภัย | รหัสผ่านเก็บเป็น PBKDF2 + salt ไม่มีรหัสจริงในฐานข้อมูล | `d1 execute ... "SELECT password_hash FROM users"` |
| NFR-S2 | ความปลอดภัย | cookie session เป็น HttpOnly | AC-A2.1 + F12 → Application → Cookies |
| NFR-C1 | ค่าใช้จ่าย | ใช้เฉพาะ Cloudflare free plan ไม่ผูกบัตร | ตรวจ dashboard |
| NFR-01 | ใช้งาน | ใช้ทุกหน้าได้บนจอกว้าง 375px โดยไม่มี scroll แนวนอน | สาธิตบนมือถือ |
| NFR-02 | ใช้งาน | ผู้ใช้ที่เคยใช้แล้วจองเสร็จภายใน 1 นาที | สาธิต + จับเวลา |
| NFR-04 | ความปลอดภัย | เห็น/ยกเลิกการจองของคนอื่นไม่ได้ | AC-3.1, AC-3.3 |
| NFR-06 | ความถูกต้อง | เวลาเป็นเวลาไทย `YYYY-MM-DDTHH:MM` ทั้งระบบ | AC-2.5 + ตรวจข้อมูลใน D1 |
